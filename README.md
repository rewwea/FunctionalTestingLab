Цель работы

Научиться разрабатывать и выполнять тест-кейсы для функционального тестирования программного обеспечения, анализировать результаты тестирования, находить дефекты и исправлять их.

Описание работы

В ходе лабораторной работы было разработано консольное приложение на языке C#, содержащее класс Calculator.

Класс содержит следующие методы:

- Add() — сложение двух чисел;
- Subtract() — вычитание;
- Multiply() — умножение;
- Divide() — деление;
- IsEven() — проверка числа на четность;
- Factorial() — вычисление факториала;
- IsPalindrome() — проверка строки на палиндром.

Для проверки методов был разработан класс CalculatorTests, выполняющий функциональное тестирование без использования сторонних тестовых фреймворков.

Проведение функционального тестирования

Для каждого метода были разработаны позитивные и негативные тест-кейсы. Также проверялись граничные значения и обработка ошибочных входных данных.

Для запуска проекта использовалась команда:

dotnet run

При первоначальном анализе программы были обнаружены проблемы с обработкой деления на ноль и отрицательного значения факториала. Дополнительно была проверена обработка строк со знаками препинания в методе определения палиндрома.

После обнаружения дефектов методы были исправлены и выполнено повторное тестирование.

Ответы на контрольные вопросы

1. Что такое функциональное тестирование и чем оно отличается от нефункционального?

Функциональное тестирование — это проверка того, правильно ли программа выполняет предусмотренные требованиями функции.

Функциональное тестирование отвечает на вопрос: «Правильно ли работает функция?».

Нефункциональное тестирование проверяет другие характеристики программы, например производительность, надежность, безопасность и удобство использования.

2. Какие виды функционального тестирования вы знаете?

Основные виды:

- позитивное тестирование;
- негативное тестирование;
- тестирование граничных значений;
- тестирование классов эквивалентности;
- предугадывание ошибок.

В работе использовались как позитивные, так и негативные сценарии.

3. Что такое тест-кейс и из каких элементов он состоит?

Тест-кейс — это описание проверки определенной функции программы.

Обычно тест-кейс содержит:

- идентификатор;
- название;
- входные данные;
- шаги выполнения;
- ожидаемый результат;
- фактический результат;
- статус прохождения теста.

4. Чем позитивное тестирование отличается от негативного?

При позитивном тестировании программе передаются корректные данные и проверяется ее нормальная работа.

При негативном тестировании используются некорректные или нештатные данные. Проверяется способность программы правильно обрабатывать ошибки.

Например, проверка Divide(6, 3) является позитивным тестом, а попытка выполнить Divide(5, 0) — негативным.

5. Что такое граничные значения? Приведите пример из работы.

Граничные значения — это значения, находящиеся на границах допустимого диапазона входных данных.

В данной работе примером является тест:

TC-ADD-05: int.MaxValue + 0

Он проверяет работу метода сложения с максимальным значением типа int.

Также граничным случаем можно считать вычисление 0!, результат которого должен быть равен 1.

6. Какие артефакты создаются в процессе тестирования?

Основные артефакты тестирования:

- тест-план;
- тест-кейс;
- чек-лист;
- тестовый набор;
- баг-репорт;
- отчет о результатах тестирования.

7. Что такое баг-репорт и какова его структура?

Баг-репорт — это документ, содержащий информацию об обнаруженном дефекте программного обеспечения.

Он может содержать:

- идентификатор дефекта;
- название;
- описание;
- серьезность;
- приоритет;
- компонент программы;
- версию ПО;
- шаги воспроизведения;
- фактический результат;
- ожидаемый результат;
- скриншоты или логи.

8. Почему важно тестировать обработку ошибок?

Обработка ошибок должна тестироваться, потому что пользователь может передать программе некорректные или неожиданные данные.

Если такие ситуации не обработаны, программа может завершиться с ошибкой или выдать неправильный результат.

В данной работе негативное тестирование позволило обнаружить отсутствие обработки деления на ноль и отрицательного значения факториала.
